## 尖銳預測:半小時會撞 `quantity INTEGER`

`step_item.quantity` 是 `INTEGER CHECK (quantity > 0)`。
而規格 `[Q13]` 白紙黑字:**半小時一個單位,會出現 0.5、1.5**。

| # | 預測 | 落空條件 |
|---|---|---|
| **B1** | 落檔 agent 撞到這一格,**不會拒絕落檔**,會自己換算(記半小時數 / 記分鐘數 / 四捨五入) | 它拒絕落檔,或整份 import 失敗收場 |
| **B2** | 換算的說明**寫在 YAML 註解裡**,而註解 import 時被丟掉 → **票 15 第三次重演** | 換算被寫進任何 store 存得下來的欄位 |
| **B3** | `unit_price_cents` 會被填進**「元」**的費率(5000 / 4200 / 3000 / 2000 / 1100),欄位名說 cents 而值是元 | 它真的乘 100 換算成分 |

B2 若成立,這就是**同一種失效在第三個位置發生**(票 08 的對譯表、票 15 的單位與客人編號、
這次的時數單位)。三次都是「agent 誠實地說明了,而說明活不過 store 那道邊界」。
