# 票 05 的預測(寫在寫程式之前,2026-08-18)

規矩同票 03:**它抓得到什麼、抓不到什麼、以什麼形式出貨,寫在跑之前。**
而且這次連**每一份語料的預期數字**都寫死 —— 對不上就是預測落空,不許事後改口。

## 它做什麼

**選項 B**:跑完之後對 run 目錄跑,跟 `provenance_check.py` 同一層。
不開表、不動 `orchestrate.py`。

判準**刻意寫笨**:

> 第 N 輪問出去的每一個題號,要出現在 **第 N+1 輪 `rN+1-questions.md` 開頭那張落點表**的某一列裡。

三個字面上的收窄,全部是故意的:

1. **「落點表」= markdown 表格的資料列**,而且在**該輪提出新問題之前**(第一個 `**Qn.` 之前)。
   散文提一句「收到了 Q8 到 Q11 的回答」**不算**落點表。
2. **只看下一輪**。隔一輪才補記的算漏接。
3. 明確答「沒有」「還沒想過」的**也算落點** —— 只要題號進了表就通過。
   (它們該進 §4 或未答追蹤,不是消失。)

## 已知上限(這幾條會印進報表,不是只寫在這裡)

1. ⚠️ **題號出現 ≠ 記對了。** 這個檢查抓得到「**整題消失**」,**抓不到「記成別的意思」**。
   後者是另一個檢查,不混進來當賣點。
2. 落點只寫在**散文**裡、或**隔一輪**才補記 → 本檢查記成漏接。**這是假陽性的方向**,
   要人去讀那一輪確認。
3. 整題沒答、只進「未答追蹤」而沒進落點表 → 也記成漏接。(現有語料沒有這種案例。)
4. **最後一輪沒有下一輪 = 不適用,不是通過。**(ADR 0005 §6)報表把它印在最上面、自成一類。

## 預期數字(逐份語料寫死 —— 這是可以落空的那部分)

**⚠️ 誠實聲明:下面的數字是我用眼睛讀完四份語料之後寫的,不是憑空猜的。**
所以它落空的方式不是「語料出乎意料」,而是 **機械判準跟人眼判讀不一致** ——
表格偵測、題號邊界、輪次配對其中一個寫歪了,數字就會對不上。那正是要驗的東西:
**「我以為的判準」和「程式實際執行的判準」是不是同一個。**

| 語料 | 可比對輪 | 通過 | 漏接 | 不適用 |
|---|---|---|---|---|
| `2026-08-18-act1-opus-rerun` | R1–R3(Q1–Q15) | **15** | **0** | R4 的 Q16–Q20(5 題) |
| `…-haiku-roleplay/roleplay` | R1–R3(Q1–Q11) | **3**(Q5–Q7) | **8**(Q1–Q4、Q8–Q11) | R4 的 Q12–Q16(5 題) |
| `…-haiku-roleplay/smoke` | R1(Q1–Q5) | **0** | **5**(Q1–Q5) | R2 的 Q6–Q10(5 題) |
| `2026-08-18-act1-interview` | **0** | — | — | 連 `rN-questions.md` 都沒有 → **無法檢查**,exit ≠ 0 |

**這是本票的已知陽性**:haiku 那場 `r2-questions.md` 與 `r4-questions.md`
**開頭根本沒有落點表** —— 第一輪的 4 題、第三輪的 4 題就這樣滑過去了,
而 `relay_ledger.verify` 全綠(答案都有被轉交)。**轉交了 ≠ 記下來了。**

反過來,opus 那場預測 **0 漏接** —— 這不是「檢查沒用」,是**它有能力印出 0**,
而 haiku 同時印出 8。一個只會印 0 的檢查跟一個只會印非 0 的檢查一樣沒用。

## 哪些結果會讓它落空(逐條)

- opus 那場出現任何**非 0** 漏接 → 我的判準跟我以為的不一樣(多半是表格偵測太嚴)。
- haiku roleplay 漏接 **≠ 8**、或通過 **≠ 3** → 題號邊界或輪次配對寫歪了。
- `Q1` 被 `Q11` 蓋掉而誤判通過(子字串比對)→ 這是最容易寫出來的 bug,
  現有語料**驗不到**(opus 的 Q1 和 Q11 都有落點),所以要用**合成測試**釘住。
- smoke 那場印出「通過」而不是 5 筆漏接 → 表格偵測沒有分辨「表在問題之前 / 之後」
  (smoke 的 `盤點` 表在問題**之後**,不是落點表)。
- interview 那場印出綠燈 → 犯了票 03 那條「**掃不到東西不算通過**」。

## 出貨形式與退出碼

- **不適用印在最上面**,自成一類,字面寫「不是通過」。
- 有任何漏接 → **exit 1**。這條判準是 `interview-prompt.md` §11 的**完成判準**
  (「指不出來 = 漏接」),不是分診建議,所以漏接 = 紅,跟 `relay_ledger.verify` 同一側。
- 可比對輪數 = 0 → **exit 1**(不是綠燈)。
- 上限那四條**印在報表尾巴**,讀報表的人拿不到票。

## §11 收尾表怎麼處理

`SPEC-draft.md` §11 是訪談者**自己寫的**逐題落點表 —— 漏了的東西不會出現在它自己列的表裡,
所以**它不進判定、不進計數、不影響 exit code**,只印成一個標明「不作數」的參考區塊。
最後一輪照樣是**不適用**,不准被 §11 折成「通過」——那是被否掉的選項 C 從後門溜回來。
