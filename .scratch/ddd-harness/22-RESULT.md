## 落空的那條:佇列 12 不是 3

**原因在預測,不在儀器**:我手算時只掃了 21–27 七張(「祖父日之後開的票」那句讓我只看新票),
但規則本身對全部 27 張跑、舊票標祖父豁免 —— 這是刻意的(ADR 0007 §Consequences 說第 4 條的
假陽性率沒驗過,「先當佇列,量過再決定」,舊票就是量它的樣本)。多出來的 9 張是 01–20 裡含
「必須 / 一律 / 慣例」的。24、25、26 如預測在佇列裡。

**順手量到的假陽性(人讀 12 條,驗過)**:

- **8 張舊票(02、03、05、06、08、09、11、12)**:關鍵字幾乎全是**受測品或檢查器的語意**
  (「fixture 若不包含…就必須填」、「已知陽性必須活著」、「宣告過的 package 必須真的有 class」),
  不是「以後別人要照做的 repo 規約」。**7 / 8 是假陽性**;只有 08 那句「欄位名一律照詞彙表對譯」
  勉強算立規,但那是規格對實作的規約,不歸 `harness_lint` 管,也不是「忘了決定」。
- **13、24、25、26 四張**:都有「## 慣例(ADR 0007)」一節,**而且都做了決定** —— 交給
  *自己那張票的檢查器*守(`innertest_landing_check` / 「由本檢查守」/ `exam.py` /「本票只讀」)。
  ADR 0007 §1 允許「進 `harness_lint` **或 pytest**」,但 §4 的判準只認 `harness_lint` 規則名
  與 `prose-only, unenforced` 兩個字串,所以它們照規格就是要進佇列。**這 4 條是判準本身的
  假陽性**(決定了,但決定的形狀不在判準的白名單裡),不是票忘了決定。
- 合計:12 條裡 **0 條是真的「忘了決定」**。這個樣本上假陽性率 100%,但樣本全是祖父票、
  而且第 4 條本來就是為之後的票寫的 —— **要不要把「由 `<某檢查器>` 守」也列進判準的白名單,
  等第一張非祖父的票進佇列再決定**(這條 ADR 自己說「佇列不是判決」)。

## 對 lint 自己的幾個判定(驗過的寫驗過,推斷的寫推斷)

- **祖父日當天 commit 的檔算祖父**(驗過:21–27、ADR 0007/0008 全 `2026-08-25`,報表「新票 0 張」)。
  後果:lint 對票 21–27 沒有牙,包括本票。`status-vocabulary` 對本票的 `done` 沒意見是因為它合規,
  不是因為祖父 —— 但若我寫 `resolved` 它也不會叫。這是 ADR 0007 §2「之後」的直接後果,不是 bug。
- **還沒 commit 的檔算新票**(驗過:`test_還沒commit的檔算新票`)。跟 Agentheim「沒日期 → 分不出來」
  刻意不同,理由寫在 `harness_lint.py` 檔頭。
- **git 不可用 → 祖父=是的規則全當祖父、不標,印在上限**(驗過:`test_git_不可用時_不標_而且印在上限`)。
- **`status-vocabulary` 對新票只放行五個詞**(needs-triage / needs-info / blocked / reopened / done)。
  票 22 表格寫「前六個」但括號寫「`resolved` 只給祖父」,兩句衝突;取括號那句,因為 `CLAUDE.md`
  說「新的一律用 `done`」。(推斷 Nat 的意圖,沒問過。)
- **Fixture 用 `GIT-DATES.txt` 假裝 git**(驗過):fixture 檔本身的 git 首次 commit 全是今天,
  分不出新舊;真 git 的管線(取最早一筆、`touch` 不算、未 commit → None)另外在 tmp repo 驗。
