### A. `landing_check.py` 有一條「掃不到東西 = 綠燈」的路徑 —— 而 05 的預測明寫它避開了這個坑

05-PREDICTION 的落空條件寫著:「interview 那場印出綠燈 → 犯了票 03 那條**掃不到東西不算通過**」。
實作的守衛是 `if rep["comparable_rounds"] == 0: return 1` —— **擋的是「沒有成對的 rN/rN+1 檔」,
不是「一題都沒比對到」**。只要檔案成對、而題號的正規式一個都沒認出來,那一輪照樣算
`compared`,`asked_total = 0`,漏接 0,**exit 0**。

證據一(合成 run,一個沒有粗體題號的 r1 + 一個 r2):

```
$ python3 tools/harness/landing_check.py $SCRATCH/fakerun
【通過】—— 題號確實出現在下一輪的落點表裡:**0 題**
  · 第 1 輪:0/0  (無)
小計:可比對 1 輪 / 0 題;通過 0、漏接 0;另有 1 題不適用(未檢查)。
EXIT=0
```

證據二(**現實的漂移**,不是我編的):把 opus 那份 run 整份複製一份,只把題號寫法
`**Q1.` 改成 `**Q1:`(四個檔全改,冒號取代句點),其他一個字不動 ——

```
mutated ok: 改了 4 個檔的題號寫法 . → :
$ python3 tools/harness/landing_check.py $SCRATCH/opuscopy
小計:可比對 3 輪 / 0 題;通過 0、漏接 0;另有 0 題不適用(未檢查)。
REAL_EXIT=0
```

**一份原本有 15 題可查的 run,因為訪談者換了個標點,靜靜地變成綠燈。**
這正是 `schema.sql` 對 `res_total_field` 那句警語的形狀:「守衛沒有壞掉,是不再適用了,
而不適用不會有人發現」——只是這次發生在為了防這件事而寫的那支檢查自己身上。

`test_landing_check.py` 全檔 14 支測試**沒有任何一支蓋這條路徑**
(`test_沒有逐輪提問檔_不算通過` 蓋的是 `rounds == []`,是另一種情況)。

> 框準一點,免得被誤讀成別的:opus 那場「5 題不適用 + exit 0」是預測裡宣告過的設計,
> **不是**這條發現。發現是「一輪被算成 compared、卻一題都沒認出來,仍然算綠」。

### C. `test_載體二` 的「破壞先生效」守衛本身是恆真形狀 —— 而且已經可以被觸發

兩支 PRAGMA 測試都用同一句守衛:

```python
stripped = schema.replace(PRAGMA_LINE, "")
assert PRAGMA_LINE not in stripped, "mutated 沒生效:那一行沒被拿掉"
```

`PRAGMA_LINE` 一旦跟 `schema.sql` 對不上(空白、換行、大小寫),`replace` 就是 no-op,
而 `X not in stripped` **恰好因此空洞地成立** —— 這正是任務描述裡那個坑的原形,今天出貨在測試碼裡。

`test_載體一` 靠後半段(拿掉之後違規列必須寫得進去)救回來了。**`test_載體二` 沒有**:
它的後半段只斷言 `build_store` 拋出含 `FOREIGN KEY` 的 `SpecError`,而**載體一還在的時候
這句話一樣成立**。實測 —— 只把 `schema.sql` 的 `PRAGMA foreign_keys = ON;` 改成語意完全相同的
`PRAGMA foreign_keys=ON;`(去掉兩個空白):

```
mutated ok: schema.sql 的 PRAGMA 寫法改成 'PRAGMA foreign_keys=ON;'(語意不變,只是空白不同)
test_載體二_匯入路徑那句PRAGMA自己就擋得住 -> 1 passed, 23 deselected
test_載體一_schema裡那句PRAGMA自己就擋得住 -> 1 failed, 23 deselected
```

**載體二那支綠著,而它此刻驗的是載體一。** 隔離已經沒了,測試名字還宣稱有。
今天不會出事的唯一理由是載體一那支會吵 —— 那是運氣,不是設計。
(修法:守衛改成 `assert stripped != schema` 或 `assert PRAGMA_LINE in schema`。)

### D. 「處置存本文不存指標」只擋行首,一個純指標寫得進去

`POINTER_ONLY = re.compile(r"^\s*(見|參見|詳見|同上|見上|如上|見前)")`。實跑四種:

```
  擋下來:'見 §9-A9'
  過了(沒擋):'不新增聚合根,詳見 §9-A9'
  過了(沒擋):'同 C12 的處置,見上'
  過了(沒擋):'處置:見 §9'          ← 純指標,沒有任何本文
```

最後一列是**完全沒有本文的指標**,只因為前面多了兩個字就過關。
ADR §3 要的是「存本文,不存『見 §9』」;實作買到的是「開頭不是『見』」。
schema 註解寫「『只寫指標』的幾種寫法認得出來」——措辭本身誠實,但
06-PREDICTION 的驗收條「處置寫成『見 §9』→ 被擋」只在字面那一種成立,別讀成規則被守住了。
