# 03 — 來源標記分不出「他真的說了」與「我餵給他、他沒否認」

**What to build:** 一個檢查:凡是宣稱出自需求方的具體值,那個值必須出現在
**需求方的回答文字裡**。拿 provenance 的宣稱去 diff 答案語料。

## 為什麼鐵律 2 擋不住

訪談 prompt 的鐵律 2 是「每條寫進 spec 的東西必須標來源;查無來源的 = 捏造」。
2026-08-18 兩場 role play 各驗到一種形狀,**兩種都產出合法的 `[Qn]`、都指得出行號**:

| 形狀 | 實例 |
|---|---|
| **A 需求方自己編** | haiku 那場:訂單編號「比如 `ORD-20260818-001` 這樣」、延遲「最好是秒級的」。凍結的 SPEC 裡 `ORD-` **0 次**,延遲一字未提 |
| **B 訪談者餵值再標成親口確認** | **opus 那場(已 commit 的產出)**:Q9 問「舉例:客人昨天用 100 元買、今天改成 120 元…」,需求方全文只答「不會,舊的那筆單就是顯示他當時下單的價格」—— **沒說過 100 或 120**。而 `SPEC-draft.md` 寫「那組數字是他在 Q9 **親口確認的**」 |

**B 比 A 隱蔽**:A 是需求方講的(至少來源真實),B 是訪談者把自己的誘導例子記成對方的話。
而下游完全看不出差別 —— 兩者的來源標記長得一模一樣。

**這是今早那條的同一家族**:
「規格沉默分不出『他沒說』與『他說了但沒送到』」→
「**來源標記分不出『他真的說了』與『我餵給他、他沒否認』**」。

## 怎麼做(草案,實作前要先寫預測)

`rounds/rN-answers.md` 就是答案語料,逐輪落地、現成的。
抽出規格裡標 `[Qn]` 的具體值(數字、格式字串、識別碼),比對它有沒有出現在對應輪次的
答案裡。**交分診佇列不是判決** —— 同義改寫、單位換算會有假陽性。

⚠️ **已知上限先寫下來**:抓得到「值沒出現在答案裡」,抓不到
「需求方自己編了一個 SPEC 沒有的值」(那是 A,要靠票 04)。
兩者都要處理才完整,但它們是不同的檢查。


**調參數的紀律**:第一版 6 筆標記裡 4 筆是題號假陽性(67%)。濾掉題號與標準編號
(`ISO 8601`)時,**用上下文濾而不是把數字加進黑名單** —— 黑名單會愈長愈像調參數,
而調到剛好讓已知陽性活著就是自欺。每加一個濾器都重跑,**已知陽性必須活著**。

**剩下的上限**(報表自己會印):單位換算與同義改寫抓不到(答案「一百二十元」vs
規格 `12000`),那是最常見的漏抓 —— **零標記不等於來源都可信**。

## 根本錯在哪

假設是「標 `[Qn]` 的行裡的具體值都應該出自需求方」。**錯。**
一行可以同時有「來自 Qn 的規則」與「自決的表示法」:

```
| QUANTITY_OUT_OF_RANGE | 400 | 數量 < 1 或 > 100 | [Q3][Q11][Q19] |
        ↑自決的命名      ↑自決  ↑ 100 才是他說的      ↑ 標記指的是「規則」
```

**推論:假陽性率與規格品質正相關 —— 它懲罰好規格。** 規格寫得越細
(詞彙表欄位、error code 表、GWT fixture、推導行),它叫得越兇。

## 教訓:偵測器的樣本要在「會讓它失效的維度」上不同

票 03 第一版寫了「拿兩個形狀不同的已知陽性驗」,而那兩個陽性
**來自同一份稀疏規格** —— 形狀不同,**規格密度相同**。
HL1/HL2 那次的關鍵維度是「fixture 共不共用」;這次是**規格的密度**,而我沒想到。

> **「兩個不同的樣本」不夠,要問:不同在哪個維度?那個維度會不會讓它失效?**

## 修的方向(未定,不要直接挑一個做)

- (a) **只掃結構化的宣稱**,不掃整行 —— 例如只掃 GWT 的 `And <欄位> = <值>`
      與詞彙表「單位/表示法」欄,跳過 error code 表與推導行
- (b) **規格側配合**:自決值一律標 `本案自決` 而不與 `[Qn]` 同行
