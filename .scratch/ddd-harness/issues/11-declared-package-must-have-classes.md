# 11 — 宣告過的 package 必須真的有 class,否則架構檢查靜靜不適用

**What to build:** 一條機械檢查:`architecture_rule` 裡宣告過的每個 package,
實作完成後必須真的含有至少一個 class。沒有的話報「**不適用**」——不算通過。

**Blocked by:** None(原料現成:store 裡就有全部宣告過的 package 名)

**Status:** **done**(2026-08-19)—— `tools/harness/package_landing_check.py` + 24 支測試。凍結骨架量到:7 宣告 / 自有 3 / **M=3** / **A1 A2 A3 A4 A6 A10 共 6 條規則整條不適用**。⚠️ 檔末另記一個未修的近親缺口(`--root` 打錯會讓離開碼翻綠)—— 已由票 14 修掉。

## 為什麼

生成的 ArchUnit 規則照規格宣告的 package 名寫死,而每條規則都帶 `allowEmptyShould(true)`。
兩件事接起來:

> **agent 只要把 class 放到別的 package,整套架構檢查就全部靜靜地不適用**
> —— 不是紅、不是報錯,是**綠**,而且看起來跟「完全遵守架構規則」一模一樣。

跟 `res_total_field` 那個坑逐字同一種:**守衛沒有壞掉,是不再適用了,而不適用不會有人發現。**

風險是真的:凍結骨架用 `com.shop.*`,訪談那份 §10 用 `order/*`,**兩套本來就對不上**。

## 形狀

- 跟 `verify_generated.py` 同一層,對編譯產出或原始碼掃一次。
- 「不適用」自成一類、印在最上面(ADR 0005 §6 那條規矩,ADR 0006 §1 沿用)。
- 「package 形狀歸規格擁有」與 ADR 0004 的「wire shape 歸規格擁有」是同一條原則的兩個實例。

⚠️ 先寫預測。可落空的寫法舉例:**預測實作完成後,宣告過的 N 個 package 裡會有 ≥1 個是空的。**

## 2026-08-19 · 落地後回報的一個未修缺口(修缺口那輪順手驗到的)

`package_landing_check.py` **沒有** `landing_check` 那條靜默綠燈的形狀
(掃到 0 個 class 時所有自有 package 都落進 empty → exit 1),**但有近親**:

> **`--root` 打錯一個字母**(`com.shop` → `com.shopp`)→ 所有自有 package 被歸成第三方
> → **離開碼從 1 變成 0**。

那支的上限段已經明寫這個失效模式(root 推導 / 排除清單),**但沒說離開碼會翻綠** ——
而「翻綠」才是會騙到人的那半。

**未修**(不在當時那三個缺口的範圍內)。修的時候一起想:離開碼要不要有第四個值
表示「root 沒對上任何 class,這次沒有檢查到任何東西」。
