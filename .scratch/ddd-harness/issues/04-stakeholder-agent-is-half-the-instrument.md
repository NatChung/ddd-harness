# 04 — 需求方 agent 是儀器的一半,但沒被當儀器管

**What to build:** 讓需求方 agent 的回答**不得超出凍結的 SPEC**,或至少讓超出的部分查得出來。

## 問題

第一幕的量測是「訪談問得出多少」,基準是凍結的 `examples/shop/spec/SPEC.md`
—— 那份就是需求方「腦中的需求」。但**沒有任何東西擋他講 SPEC 裡沒有的東西**。

2026-08-18 haiku 那場實測:

- 訂單編號「比如 `ORD-20260818-001` 這樣」 → SPEC 裡 `ORD-` 出現 **0 次**
- 延遲「最好是秒級的」 → SPEC 一個字都沒提效能

他的 prompt 明寫「**你心裡沒有的東西就說你還沒想過。不要現編。**」

有意思的是他**守得住範圍、守不住細節**:被問庫存 / 付款 / 地址 / 後續狀態時,
正確答「先不考慮」(與凍結 SPEC 的〈明確不在範圍〉一致);
**被問具體格式時就現編一個**。

## 為什麼這會壞掉量測

產出的規格會有「**有來源但無依據**」的規則:它指得出 `[Qn]`、逐字稿裡真的有那句話,
但那句話本身是 agent 編的。於是:

- **完整度的基準浮動** —— 拿產出去比凍結 SPEC 時,多出來的條目分不清是
  「訪談問出了 SPEC 沒寫的東西」還是「需求方現編的」
- 票 03 的檢查**抓不到這一種**(值確實出現在答案裡),所以兩張票要各做各的

## 方向(未定,要先討論)

- (a) 收緊需求方的 prompt(最便宜,但靠自覺,而「靠自覺守不住」是這條線的反覆教訓)
- (b) 事後檢查:需求方答案裡的具體值,比對凍結 SPEC —— 交分診佇列
- (c) 換掉 agent 模擬:改成腳本化的需求方(問什麼答什麼查表),
  **但那會讓第一幕不再是訪談** —— 訪談的價值有一半在「他答得含糊、要追問」

⚠️ (c) 動到的是第一幕的性質,不只是實作 —— **要 grill 過再動**。
