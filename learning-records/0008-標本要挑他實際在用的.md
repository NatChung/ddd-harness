# 刪掉第 7 課:標本挑錯了

2026-08-11,第 7 課(拆 Spec Kit)產出當天,Nat 看完直接說:

> 我覺得第 7 課沒有必要存在,我自己常用的 Superpowers skills,目前換成 matt-pocock skills

判斷成立,當天刪除。這則記的不是他學到什麼,是**教材設計上的一個錯**。

## 錯在哪

那課的能力目標沒問題——它直接對應 MISSION 的成功條件之一:
「看得懂別人在講 SDD / agent harness 時,哪些是既有概念換皮,哪些是真的新東西。」

**錯的是標本。** 挑了 Spec Kit,理由是「業界最常被引用的參考實作」。
但 Nat **不用它、也不打算用**。拆完之後他手上什麼都沒變——
而這個練習的全部價值,就在於「拆完能改進自己的東西」。

更糟的是,更好的標本一直都在,**而且就在這個 repo 裡**:

```
docs/agents/domain.md / issue-tracker.md / triage-labels.md   ← mattpocock-skills 的慣例
.scratch/worklog-sync/                                        ← 真的跑過的 ticket 目錄
CONTEXT.md                                                    ← 用 /domain-modeling 維護的 glossary
```

而且他**用過 Superpowers、現在換成 mattpocock-skills**——兩套都跑過,做得了對照。
那比看單一工具有價值得多(例:同樣要處理「規格含糊」,Spec Kit 用
`[NEEDS CLARIFICATION]` 標記擋,mattpocock-skills 看起來是用 grilling 那組 skill
面談逼出來 + `needs-info` label;同一個問題兩種機制)。

## 通則

**教材裡的標本要挑他實際在用的東西,不要挑「業界最常被引用的」。**

「最常被引用」是寫給不特定讀者看的教材才需要的判準。這份教材只有一個讀者,
而且他手上有真實系統與真實 harness。挑他用的東西,對照表的最後一欄會從
「所以那個工具有這個」變成「**所以我這套缺這個,下一步補它**」——那才是 mission 要的。

這條同時適用於 NOTES 裡還沒定案的「**貫穿案例**」:
目前用中性小型電商例子,但**他自己的 harness 與這個 repo 本身**是更好的候選。

## 也值得記的

- **他會對課程本身下判斷,不只是被動接收。**「這課沒必要存在」是很有價值的回饋,
  而且他給了替代方案(我在用的是另外兩套)。往後產出新課時可以更早問他
  「這個例子對你有用嗎」,不必等整課寫完。
- 刪除的成本不高:查證過的引用句全數留在 RESOURCES.md,檔案本身移出 workspace
  (未進 git)。**真正浪費的是挑標本那一步的判斷,不是寫作。**
