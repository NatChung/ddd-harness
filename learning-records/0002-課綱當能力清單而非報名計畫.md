# Mission 釐清:Teddy 的課綱是「能力清單」,不是報名計畫;工程底子紮實

2026-08-09,Nat 貼了陳建村(Teddy)「馴服 AI 寫出可維護的系統:模式語言驅動開發工作坊」的
課程頁,說明他學 DDD 是為了這個。追問後他明確表示:**「我沒有要上他的課,貼這個只是想讓你
知道我是為什麼而學 DDD」**。

同時揭露技術背景:**Java、物件導向、design patterns、單元測試(xUnit)都熟。**

## Implications

- **課綱 = 驗收清單。** 那份課綱(pattern language 多層次運用、sub-agent prompt template、
  自動化 workflow pipeline、從 AI 錯誤演化 pattern、BDD + Design by Contract 品保)
  精準描述了 Nat 想自己做到的能力,已寫進 MISSION.md 的 Success looks like。
  **但不要再提報名、早鳥、費用、日期**——那條路他已經否決了。
- **Clean Architecture、CQRS、Event Storming、Design by Contract 從 out-of-scope 移入 in-scope。**
  理由不是「先修門檻」(他不去上課,沒有門檻),而是課綱裡的 harness 本來就架在這些概念上,
  少了它們 pattern language 只剩領域層,指揮不動 agent 做完整 feature。
  Event Sourcing 仍然排除。
- **教學節奏可以加快、抽象層次可以拉高。** 他 DDD 零基礎但工程底子紮實,
  所以新概念要**接到他已經會的東西上**教,而不是從頭鋪:
  Aggregate ↔ 物件封裝與 invariant;Repository ↔ 他寫過的 DAO;
  BDD ↔ 他熟的 xUnit(差別在誰讀得懂、以及驗收的粒度)。
  範例可以直接寫 Java,不需要偽代碼。
- **「pattern language」是本 mission 的核心概念,而且尚未教。**
  它是課綱的主軸(Christopher Alexander 的概念,經 GoF 進入軟體),
  也是把 DDD 的各層 pattern 串成「指揮 agent 的詞彙」的那個框。
  目前的課表(UL → Bounded Context → BDD)是它的地基,但**要在某一課明確把這個框講出來**,
  否則學完會是散的 pattern 而不是 language。
