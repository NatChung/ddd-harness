# 訪談 prompt —— 逐版改動與依據

**這份不是受測品的一部分。** 它從 `interview-prompt.md` 檔末搬出來(2026-08-17),
理由見 `runs/2026-08-17-interview-cross-model/PROVENANCE.md` 的「剝離」段:
嵌在受測品裡時,它點名了 14 條必填欄中的 6 條並附「前幾輪漏掉這個」,
對一個產出是「欄位排序」的實驗來說,那是差別放大器。

它留著,因為併進 skill v5 時要用 —— 每條機制的**依據**在這裡,不在 git message 裡。

## 改動紀錄

| # | 改了什麼 | 依據 |
|---|---|---|
| 1 | 來源標記 3 格 → **5 格**;`模板既定` 加文件白名單 | 兩輪 role play 各自發明一個標籤(`暫定`、`推導自`);對照組拿訪談指示本身冒充架構模板 |
| 2 | 刪題數上限,改成**每題標靶 + 未答追蹤 + 技術/政策分流** | 「最多 5 題」被 (a)(b)(c)(d) 形式繞過,實際問 18 題;全答之後規格沉默反而 18 → 22 條 |
| 3 | 追問表與產出合約**逐列對齊**;補 Value Object / Domain Event / 系統中途失敗 | 兩輪都缺這三樣,且**資訊充足的對照組照樣缺**——證明是產出合約的洞,不是資訊的洞 |
| 4 | invariant / precondition 加**「守在哪個聚合根內」**必填欄 | 兩輪都有跨聚合根的規則沒被抓到(輪 1 的 I1、對照組的 C-03/04/05);對照組甚至拿其中一條當聚合根邊界的**依據** |

**其中第 3 條的「系統中途失敗」與「指名測試」不是新發明**——現行 skill v2/v4 早有,
v0 漏帶。這兩項算**修復退步**,不算改進。

### v1 → v2

| # | 改了什麼 | 為什麼 |
|---|---|---|
| 5 | 補 **§9 ARCHITECTURE**、**§10 PROMPT** | v1 只交 GLOSSARY 與 SPEC 兩份的內容,**比 skill v4 少三份**。受測品的範圍若與 skill 不相當,測出來的結論就搬不進 skill,將來得再測一輪 |
| 6 | 補 **§11 INTERVIEW-LOG** 的**逐題落點對照** | v1 的回鏈只有「規則 → `[Qn]`」(防捏造)。反方向「`[Qn]` → 規則」(防**漏接**)v1 與 skill v4 **都沒有** |
| 7 | 追問表補一列:「這一段是誰負責」→ §1.1 + §9 | 補了 §9 之後,追問表必須有一列餵它 —— 否則又是「有欄位沒人填」,那正是 v1 修掉的病 |

**第 5、7 條是補範圍(scope parity),第 6 條是唯一的新機制。** 刻意沒做的兩件事:

- **沒有納入 skill 的 v5 候選**(「已被 ArchUnit 強制的規則不該由 ARCHITECTURE 複述,
  應收緊成指名那條測試」)—— 那條尚未驗證,混進來會讓歸因更糊。
- **沒有改 v1 的任何既有條文。** v1 的 baseline 還要當對照組。
