## 0. 訪談內部矛盾（必須由需求方裁決，不自行調和）

**CONFLICT-01：「一定要收到貨才退錢」與「查不到就直接退」互斥。**

- [R1Q3]：「一定是收到貨才退錢，我們不會先退錢再收貨，**這個沒有例外**。」
- [R1Q5a]：客人說寄了但我們沒收到 → 物流查不到的話，「2000 元以下公司吸收、**直接退款**給客人」。

這兩條同時成立時，2000 元以下的無貨爭議路徑會直接違反前一條。可能的裁決方向有兩種
（**不代表建議，只是把選項攤開**）：把 [R1Q5a] 定義成 [R1Q3] 的具名例外，或把它定義成
「不是退貨退款、是理賠/善意補償」的另一種單據。**這題沒問過，不自決。**
在裁決前 **C-30** 標「invariant，待確認」，實作不得以任一解讀開工。

## 1. GLOSSARY 片段

跨部門詞彙分歧是 [R1Q1] 明講的：客服／倉庫／財務講「退貨」各指不同的事。依
`模板既定 (v0 L23)`，切成三個 Bounded Context，各自保留自己的詞，跨界一律以**退貨單號**關聯。

### 1.1 聚合 / 識別

| 詞 | 定義 | 型態 / 單位 | 來源 |
|---|---|---|---|
| **退貨單** | 從客人提出到錢退出去的**整件事**，一張單。內部禁用「退貨案件」 | Aggregate Root | [R2Q3] |
| **退貨單號** | 退貨單的唯一識別 | 字串識別碼；**格式未定** | [R2Q3]；格式為規格沉默 |
| **退貨明細行** | 一張退貨單內的一個退貨品項。因可部分退、按件算錢，行才是計價單位 | 退貨單內部 entity | 推導自 [R1Q4] |

### 1.2 三個 Bounded Context 的詞

| 詞 | 屬哪個 Context | 定義 | 型態 | 來源 |
|---|---|---|---|---|
| **退貨申請** | 客服 | 客人提出要退、以及客服審核那一段 | 退貨單的階段 + 一次審核動作 | [R1Q1][R2Q3] |
| **退貨驗收** | 倉庫 | 貨真的寄回來、驗收入倉那件事 | 退貨單的階段 + 一次驗收動作 | [R1Q1][R2Q3] |
| **退款** | 財務 | 錢出去的那一筆。財務不講「退貨」，只講退款 | 一筆出款交易 | [R1Q1][R2Q3] |

> 「退貨」這個裸詞在跨部門文件／API 命名中**禁用**，因為三方各指一件事 [R1Q1]。

### 1.3 時間

| 詞 | 定義 | 型態 / 單位 | 來源 |
|---|---|---|---|
| **簽收日** | 客人簽收該訂單那天。七天的起算基準（不是出貨日） | 日期（date） | [R2Q1a] |
| **可退期限** | 簽收日 + 7 天當天的 `23:59:59`。是**日界**，不是滿 7×24 小時 | 時間戳，秒精度 | [R2Q1b] |
| **寄回期限** | 客服審核通過起算 5 天內要把貨寄出 | 期間，日 | [R2Q2a] |
| **逾期提醒** | 寄回期限失效**前一天**發出的提醒 | 事件 | [R2Q2b] |
| **失敗名單檢視時點** | 每日 `10:00`，財務看退款失敗名單 | 每日固定時刻 | [R1Q5d][R2Q5c] |
| **重試間隔** | 退款失敗後每次重試相隔 1 小時 | 期間，小時 | [R1Q5d] |

### 1.4 金額

| 詞 | 定義 | 型態 / 單位 | 來源 |
|---|---|---|---|
| **幣別** | 只有台幣，無外幣 | TWD 固定 | [R2Q4a] |
| **商品價格** | 一律整數元 | 整數，TWD | [R2Q4b] |
| **運費** | 會有到角的小數，例：35.5 元 | 小數，TWD | [R2Q4b] |
| **金額表示** | 全域金額型態 | Decimal（scale ≥ 2），**禁用 float** | 本案自決 A-02 |
| **原訂單運費** | 客人當初出的去程運費。**不退** | Decimal, TWD | [R1Q4] |
| **回程運費** | 貨寄回來的運費。**客人自付**，任何情況都不由公司吸收 | Decimal, TWD | [R1Q4][R1Q5b] |
| **券分攤額** | 折扣券按**原價比例**分攤到每個明細行的折扣 | Decimal, TWD | [R1Q4][R2Q4c][R2Q4d] |
| **零頭處理** | 分攤除不盡時，**無條件進位、多的給客人，公司吸收** | 進位方向：對客人有利；**進位到哪一位未定（見 SILENT-02，阻斷）** | [R1Q4][R2Q4c] |
| **可退金額** | Σ（明細行商品價格 − 該行券分攤額）；**不含任何運費** | Decimal, TWD | 推導自 [R1Q4] 各項 |
| **無貨吸收上限** | 2000 元。以下公司吸收直接退，以上要客服主管拍板 | Decimal, TWD；**「2000」比的是哪個金額未定（見 SILENT-03）** | [R1Q5a][R2Q5b] |
| **特批單筆上限** | 10000 元 | Decimal, TWD；**比的是哪個金額未定（見 SILENT-03）** | [R2Q5a] |

### 1.5 判定依據與人

| 詞 | 定義 | 型態 | 來源 |
|---|---|---|---|
| **規則表** | 客服審核照著判的那份表。表上沒寫到的才走特批 | 外部管理的規則集；**內容/維護者/版本策略未定** | [R1Q2] |
| **驗收標準表** | 倉庫判「有沒有用過」的那份表 | 外部管理的規則集；**內容/維護者未定** | [R2Q1c] |
| **客服主管特批** | 唯一有特批權的角色。月上限 20 次、單筆 ≤10000、必須留紀錄（誰批、為什麼） | 授權動作 + 稽核紀錄 | [R2Q5a] |
| **失敗名單** | 退款重試 3 次都失敗後進入的名單 | 集合 | [R1Q5d] |
| **生鮮食品** | 一律不可退的品類，「沒得談」 | 商品品類旗標 | [R1Q2] |
| **拆封 / 使用過** | 拆開看一下**不算**用過。客服前端只憑客人照片先擋明顯有問題的，**最終認定權在倉庫** | 驗收判定 | [R1Q2][R2Q1c] |
| **通知** | email + 簡訊都發，三個時點：審核結果出來 / 倉庫收到貨 / 退款完成 | 通知事件 × 2 通道 | [R2Q5 補充] |

## 2. GWT 清單（含失敗路徑）

### 2.1 申請與資格

**GWT-01 期限內申請成立** `[R1Q2][R2Q1a]`
Given 某訂單簽收日為 D、商品非生鮮且未退過
When 客人在 D+7 的 23:59:59 前提出退貨申請
Then 建立退貨單，狀態進入待客服審核

**GWT-02 期限邊界（過期）** `[R2Q1b]`
Given 簽收日為 D
When 客人在 `D+7 23:59:59` 之後提出申請
Then 拒絕受理，理由為逾七天期限
（邊界測資必須含 `D+7 23:59:59` 通過、`D+8 00:00:00` 拒絕；**不得以滿 7×24 小時實作**）

**GWT-03 生鮮一律不可退** `[R1Q2]`
Given 品項為生鮮食品
When 客人申請退貨
Then 拒絕，且**特批不適用**（`推導自 [R1Q2]`：「沒得談」+ 特批範圍限於「表上沒寫到的例外」，他未逐字說特批不適用）

**GWT-04 已退過不可再退** `[R1Q2]`
Given 該品項已經退過
When 客人再次申請
Then 拒絕
（「退過」的口徑未定，見 SILENT-01，**阻斷此條實作**）

**GWT-05 拆封未使用可退** `[R1Q2][R2Q1c]`
Given 商品已拆封但未使用
When 客人申請並附照片
Then 客服憑照片不得以「已拆封」為由退件；是否使用過由倉庫驗收最終認定

**GWT-06 同品項第三次申請被擋** `[R1Q5c][R2Q2d]`
Given 同一品項已申請過 2 次
When 客人再次申請
Then 拒絕
（計次是否含取消/逾期失效未定，見 SILENT-01）

**GWT-07 同訂單第四張退貨單被擋** `[R2Q4e]`
Given 同一張訂單已產生 3 張退貨單
When 客人再對該訂單申請
Then 拒絕

### 2.2 客服審核

**GWT-08 審核通過** `[R2Q2a][R2Q5 補充]`
Given 退貨單待審核且符合規則表
When 客服審核通過
Then 狀態進入待寄回；設定寄回期限 = 通過時間 + 5 天；發 email + 簡訊通知客人審核結果

**GWT-09 審核不通過** `[R1Q5c][R2Q5 補充]`
When 客服審核不通過
Then 狀態進入審核未過；**必須帶說明原因**；發 email + 簡訊通知客人；客人可補資料重新申請

**GWT-10 規則表外的例外由主管特批** `[R1Q2][R2Q5a]`
Given 情境不在規則表內
When 客服主管特批通過
Then 退貨單以特批放行；**同時產生一筆特批紀錄，含核准人與理由**

**GWT-11 特批當月超額** `[R2Q5a]`
Given 客服主管當月特批已達 20 次
When 他再送出一筆特批
Then 拒絕（「一個月最多 20 次」是**單一主管**或**全公司**未定，見 SILENT-04）

**GWT-12 特批金額超上限** `[R2Q5a]`
Given 該筆金額 > 10000 元
When 客服主管特批
Then 拒絕

**GWT-13 非客服主管嘗試特批** `[R2Q5a]`
Given 操作者不是客服主管（含一般客服、倉庫、財務）
When 他嘗試特批
Then 拒絕（「特批只有客服主管能批，別人不行」）

### 2.3 寄回與取消

**GWT-14 逾期未寄回自動失效** `[R2Q2b]`
Given 退貨單已審核通過、寄回期限為 T
When 到 T 客人仍未寄回
Then 退貨單自動失效
And 在 T 的前一天已發出提醒

**GWT-15 倉庫簽收前可取消** `[R2Q2c]`
Given 倉庫尚未簽收退回的貨
When 客人要求取消
Then 取消成功

**GWT-16 倉庫簽收後不可取消** `[R2Q2c]`
Given 倉庫已簽收
When 客人要求取消
Then 拒絕（「倉庫一收到貨就不能取消了」）

**GWT-17 自行取消後可再申請，但仍受七天期限** `[R2Q2d]`
Given 客人自行取消過一次、且**仍在**簽收日 +7 天期限內
When 他再次對同品項申請
Then 受理
And 若已過七天期限 → 拒絕（「過期就沒了」）

### 2.4 倉庫驗收

**GWT-18 驗收合格** `[R1Q3][R2Q5 補充]`
Given 退回商品符合驗收標準表、未使用
When 倉庫驗收通過
Then 入庫；狀態進入待退款；發 email + 簡訊通知客人「已收到貨」

**GWT-19 驗收不合格擋下** `[R1Q5b]`
Given 收到的東西壞了 / 少件 / 不是原本那件
When 倉庫驗收
Then **不入倉**；退回客服處理

**GWT-20 客服談成補齊** `[R1Q5b]`
Given 驗收不合格已退回客服
When 客服與客人談定由客人把缺的補齊
Then 退貨單回到待驗收

**GWT-21 客服談成整張作廢** `[R1Q5b]`
Given 驗收不合格已退回客服
When 客服與客人談定整張作廢
Then 退貨單作廢；貨寄回客人；回程運費由客人負擔
And **不產生退款**（`推導自 [R1Q5b]`，他沒逐字說「不退款」，作廢即無退款是必然，仍標為推導）

### 2.5 退款

**GWT-22 部分退的金額計算** `[R1Q4][R2Q4c][R2Q4d]`
Given 一張訂單只退其中幾件
When 計算可退金額
Then 只算那幾件的商品金額
And 折扣券按原價比例分攤、只退那幾件對應的部分
And 原訂單運費不退、回程運費不退
And 分攤除不盡的零頭無條件進位給客人、公司吸收
（進位到哪一位未定，見 SILENT-02，**阻斷此條實作**）

**GWT-23 退款成功** `[R1Q4][R2Q5 補充]`
Given 退貨單狀態為待退款
When 財務出款成功
Then 退回原本付款方式（刷卡退回原卡）；發 email + 簡訊通知客人退款完成

**GWT-24 退款失敗自動重試** `[R1Q5d]`
Given 金流回報退款失敗
When 系統處理
Then 自動重試，每次間隔 1 小時，最多 3 次

**GWT-25 三次都失敗進名單** `[R1Q5d][R2Q5c]`
Given 已重試 3 次仍失敗
When 第 3 次失敗
Then 退貨單進失敗名單
And 財務於次日 10:00 檢視名單
And 客服聯絡客人換帳戶

**GWT-26 換帳戶需主管核准** `[R1Q5d]`
Given 客人提供新的收款帳戶
When 客服要改退款去向
Then 需客服主管核准才生效

### 2.6 貨沒收到的爭議

**GWT-27 查不到、金額在門檻以下** `[R1Q5a][R2Q5b]`
Given 客人主張已寄出、公司未收到
When 客人提供寄件單號、向物流查詢查不到、且金額 ≤ 2000 元
Then 公司吸收、直接退款給客人
（**與 CONFLICT-01 衝突，實作前需裁決**）

**GWT-28 查不到、金額超過門檻** `[R1Q5a][R2Q5b]`
Given 同上但金額 > 2000 元
When 處理
Then 需客服主管核准才退款；未核准前不得出款

## 3. 領域契約清單

分類方法依 `模板既定 (v0 L25)`：呼叫方錯 = precondition／實作方錯 = postcondition／隨時要成立 = invariant。

### 3.1 建立退貨單

| # | 類別 | 契約 | 來源 |
|---|---|---|---|
| C-01 | **pre** | 建立時 `now ≤ 簽收日 + 7 天 23:59:59`（該日時區見 A-01） | [R1Q2][R2Q1] |
| C-02 | **pre** | 每個明細行的品項不得為生鮮食品；此條**不可被特批豁免**（不可豁免為 `推導自 [R1Q2]`） | [R1Q2] |
| C-03 | **pre** | 該品項「不能是已經退過的」（原話口徑，見 SILENT-01） | [R1Q2] |
| C-04 | **pre** | 同一品項的申請次數 < 2 | [R1Q5c][R2Q2d] |
| C-05 | **pre** | 同一張訂單已存在的退貨單數 < 3 | [R2Q4e] |
| C-06 | **post** | 建立成功後配發唯一退貨單號 | [R2Q3] |
| C-26 | **invariant** | 退貨單所有金額幣別恆為 TWD | [R2Q4a] |

### 3.2 審核與特批

| # | 類別 | 契約 | 來源 |
|---|---|---|---|
| C-07 | **pre** | 特批：情境不在規則表涵蓋範圍內 | [R1Q2] |
| C-08 | **pre** | 特批：執行者角色 = 客服主管 | [R2Q5a] |
| C-09 | **pre** | 特批：該主管當月已用特批次數 < 20 | [R2Q5a] |
| C-10 | **pre** | 特批：單筆金額 ≤ 10000 元 | [R2Q5a] |
| C-11 | **post** | 特批成立必產生稽核紀錄，含核准人與理由，兩者皆不可為空 | [R2Q5a] |
| C-12 | **post** | 審核不通過必帶「原因」欄位，不可為空 | [R1Q5c] |
| C-13 | **post** | 審核通過後，寄回期限 = 通過時間 + 5 天 | [R2Q2a] |
| C-14 | **post** | 寄回期限到期前一天必已發出提醒 | [R2Q2b] |

### 3.3 取消與驗收

| # | 類別 | 契約 | 來源 |
|---|---|---|---|
| C-15 | **pre** | 取消：倉庫尚未簽收該退回貨品 | [R2Q2c] |
| C-16 | **invariant** | 驗收不合格（破損／少件／錯件）的貨**不得入倉** | [R1Q5b] |
| C-17 | **invariant** | 「是否使用過」的最終認定權在倉庫；客服的照片初篩不構成認定 | [R2Q1c] |

### 3.4 金額

| # | 類別 | 契約 | 來源 |
|---|---|---|---|
| C-18 | **invariant** | 退款金額**永不含**原訂單運費 | [R1Q4] |
| C-19 | **invariant** | 回程運費**永不由公司負擔**（含整張作廢寄回客人那條路徑） | [R1Q4][R1Q5b] |
| C-20 | **post** | 券分攤採原價比例；零頭朝對客人有利的方向無條件進位，差額由公司吸收 | [R1Q4][R2Q4c] |
| C-21 | **post** | 部分退時，券只退對應明細行的那部分，不得整張券折扣全額吐回 | [R2Q4d] |

## 5. ASSUMPTIONS（本案自決，四條，非決不可）

| # | 自決 | 依據 |
|---|---|---|
| A-01 | 所有日期／日界時間以 **Asia/Taipei (UTC+8)** 判定 | [R2Q1b] 用 `23:59:59` 這種日界表示法，日界不綁時區就無法判定；[R2Q4a] 只收台幣，業務落在台灣 |
| A-02 | 金額型態一律 **Decimal（scale ≥ 2）**，禁用二進位浮點數 | [R2Q4b] 運費含小數；[R2Q4c] 進位規則要求可精確重現，浮點誤差會讓「多給客人」變成「少給客人」 |
| A-03 | **退貨單 = Aggregate Root**，退貨明細行是其內部 entity；一致性邊界落在退貨單 | [R1Q4] 按件退、[R2Q4e] 一張訂單最多 3 張退貨單 → 退貨單才是不變式（次數、金額、狀態）的守門者 |
| A-04 | 客服／倉庫／財務切為三個 Bounded Context，跨界一律以**退貨單號**關聯，不共用「退貨」裸詞 | [R1Q1] 三部門同詞異義；`模板既定 (v0 L23)` |
