**目的不是量訪談品質。** 用便宜的模型跑,先確認修好的第一幕**在真跑上**成立,
再決定要不要花 opus 那一趟($10–20)。兩場的 model 與受測輸入 blob 記在各自
`run-meta.json`,不靠事後回憶。

## 追問表的骨架跨模型穩定,問法的品質不穩定

第 1 輪五個槽位,haiku 與 opus **完全相同、只有順序不同**:
訂單成立時點 / 訂單要有哪些資料 / 誰看列表 / 要不要擋什麼 / 之後發生什麼。
→ **問題集合是 prompt 的追問表決定的,不是模型決定的。**(n=1,不能當結論。)

品質差別出現在會影響規格的地方:

- **haiku 誘導答案**:「具體涉及哪些信息?比如客人要選什麼(商品?金額?數量?運送地址?)」
  —— 把選項餵給不懂技術的人,他多半照著挑。opus 問的是開放式的。
- **haiku 問了範圍外的東西**:Q7 問延遲 SLA(「30 秒行不行?」)—— SPEC 完全沒有這件事,
  而且那不是該問非技術需求方的問題。
- **落點標記精度掉一階**,細到不足以事後查漏。
- 簡體中文,違反明確指示。

## ⚠️ 新的失效模式:來源標記分不出「他真的說了」與「我餵給他、他沒否認」

**兩場各出現一種形狀,而且鐵律 2(查無來源 = 捏造)兩種都擋不住** ——
因為兩種都產出合法的 `[Qn]`,都指得出逐字稿行號。

| 形狀 | 哪一場 | 實例 |
|---|---|---|
| **A 需求方自己編** | haiku | 訂單編號「比如 `ORD-20260818-001` 這樣」、延遲「最好是秒級的」。凍結的 SPEC 裡 `ORD-` 出現 **0 次**,延遲一個字都沒提。它的 prompt 明寫「不要現編」 |
| **B 訪談者餵值再標成親口確認** | **opus(今早那場,已 commit)** | Q9 問「舉例:客人昨天用 **100** 元買、今天改成 **120** 元…」,需求方全文只答「不會,舊的那筆單就是顯示他當時下單的價格」—— **從沒說過 100 或 120**。而 `SPEC-draft.md` 寫「那組數字是**他在 Q9 親口確認的**」 |

B 比 A 隱蔽得多:A 至少是需求方講的,B 是訪談者把自己的例子記成對方的話。

**這條機械查得到**:凡是宣稱出自需求方的具體值,那個值應該出現在**需求方的回答文字裡**。
拿 provenance 的宣稱去 diff 答案語料就抓得到。→ `.scratch/ddd-harness/issues/03`

順帶:haiku 的需求方**守得住範圍、守不住細節** —— 被問庫存/付款/地址/狀態時
正確答「先不考慮」(與凍結 SPEC 的不在範圍一致),被問具體格式時就現編一個。
→ 需求方 agent 也是儀器的一半,見 `.scratch/ddd-harness/issues/04`
