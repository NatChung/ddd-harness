### 為什麼崩:它懲罰好規格

早上那份規格稀疏,`[Qn]` 那幾行幾乎只有需求方講的東西。
這份有詞彙表欄位、error code 表、GWT fixture、`推導自` 的推理行 ——
**越多自決值落在標 `[Qn]` 的行上,它叫得越兇。**

> **偵測器的假陽性率與規格品質正相關。**

根本錯在假設:「標 `[Qn]` 的行裡的具體值都應該出自需求方」。
實際上**一行可以同時有「來自 Qn 的規則」與「自決的表示法」** ——
`| QUANTITY_OUT_OF_RANGE | 400 | 數量 < 1 或 > 100 | [Q3][Q11][Q19] |`
這一行的來源標記指的是**規則**,而 error code 名與 400 是自決的。

### 這是第三次重演同一條教訓

**一個樣本證明不了偵測器。** 票 03 明明寫了「拿兩個形狀不同的已知陽性驗」,
但那兩個陽性**來自同一份稀疏規格** —— 形狀不同,**規格品質相同**。
真正的第二個樣本要是**另一種品質的規格**,而那個樣本今天才出現。

→ **偵測器的樣本要在「會讓它失效的維度」上不同,不是隨便兩個不同就算。**
HL1/HL2 那次的維度是「fixture 共不共用」;這次的維度是**規格的密度**,而我沒想到。

## ⚠️ 我自己的預測寫壞了一條

`PREDICTION.md` 寫的是「`provenance_check` 標記數 **> 0**」。

**那是一個不可能失敗的預測** —— 任何非零結果都算中。實際上它標了 52 筆、
真陽性 0 筆,而預測「中了」。**這正是這條線一直在打的假驗收,我犯在預測檔裡。**

正確的寫法是「標記數 > 0 **且真陽性 ≥ 1**」。
→ **寫預測時先問:有沒有哪個結果會讓這條預測落空?答不出來就是還沒寫成預測。**
