## 第二輪:問題

**Q6. 那個「單價」是誰決定的?**
客人送單過來的時候,價格是他那邊帶過來的,還是系統自己去商品資料裡查出來的?
還有一個接著的問題:如果某個商品**明天調價**了,上個月已經成立的那些舊訂單,金額會跟著變嗎?還是要永遠停在他當初買的那個價?
(補:§3 invariant C1 的可實作性 + 「單價」是否為訂單的快照;§1 GLOSSARY 單價)

**Q7. 一張訂單會經過哪幾種狀態?**
你在 Q4 說清單要看「現在狀態,像已成立這樣」——「已成立」以外還有哪些?請把你會用到的講法都念一遍給我聽(出貨了叫什麼、客人不要了叫什麼、錢還沒付叫什麼……)。哪些狀態之間可以互相走、哪些絕對不可能倒回去?
(補:§1 GLOSSARY「訂單狀態」判定為「階段或狀態」型態;§3 狀態轉移 precondition)

**Q8. 訂單一旦成立,**你這邊接著會**發生什麼事、或有誰要被通知?**
比方說倉庫要收到出貨通知、會計要記一筆、客人要收到確認信……有的話請說;**如果目前真的什麼都不會發生,也請直接說「沒有」**,我需要把「沒有」寫進規格,不是留白。
(補:§4 Domain Event 清單——這一節不得為空,空的話要寫明為什麼空)

**Q9. 下單按下去、跑到一半系統掛掉,你希望結果是什麼?**
客人按了送出,結果網路斷掉/機器重開,他看不到任何回應。這種時候:那張單**算成立還是不算**?你能不能接受系統裡留下「一張只寫了一半的單」(例如有訂單、但品項只存進去三樣中的兩樣)?還有,客人如果不確定、又按了一次送出,你希望變成一張還是兩張?
(補:§2 GWT 失敗路徑第 3 類「系統中途失敗」;§3 失敗 postcondition 的原子性保證)

**Q10. 那個「客人編號」是哪裡發的?**
是你們另一套系統/另一個部門在管的嗎?下單的當下,系統要不要先去確認「這個編號真的有這個人」?**如果查不到、或那邊剛好連不上,你希望這張單怎麼辦**——擋掉、還是先收下來再說?另外,清單上的客人名字,是要即時去那邊撈,還是下單當下就抄一份存在訂單裡?
(補:§1.1 Bounded Context 邊界 + §9 相依方向;§2 GWT 失敗路徑第 2 類「外部系統回失敗」)
