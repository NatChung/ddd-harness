Q1. 「工時單」這件事裡,是誰把工時填進去、誰看、誰拿它去跟人收錢?這三個角色是同一個人還是分屬不同部門?另外,**你自己在這件事裡是哪個角色**(要填單的人、要收錢的人、還是負責做這套系統的人)?(補:小尺度—GLOSSARY 角色;若跨部門 → 大尺度 §1.1 Bounded Context)

Q2. 現在這件事你們是怎麼做的?有沒有已經在跑的系統(工時、專案、發票、薪資、客戶資料)?新做的這個要不要跟其中哪一個對接?(補:大尺度 §9 相依方向;§5 明確不在範圍)

Q3. 你們有沒有一份已經寫定、被授權當標準的**開發規範或架構模板文件**(分層、package 佈局、相依方向)?有的話它叫什麼、在哪?(補:大尺度 §9「出處」——沒有的話 `模板既定` 必為零筆)

Q4. 你自己看不看得懂技術細節(例如 API 欄位怎麼命名),還是我該全程用業務語言問你、技術面的東西我自己決定?(補:§1.2 wire shape 是否純 `本案自決`)

Q5. 「計費」的那個金額,是怎麼算出來的?費率是掛在**人**身上、**角色**身上、**專案**身上,還是**客戶**身上?(補:小尺度—GLOSSARY 量值;微尺度—計費規則的 invariant 落點)

Q6. 一張工時單從被建立,到「可以拿去跟客戶收錢」為止,中間會經過哪些階段?每個階段是誰動它的?(補:小尺度—GLOSSARY「階段或狀態」;需求尺度 §2 GWT 的動作清單)

Q7. 已經拿去跟客戶收過錢的那些工時,還能不能改或刪?(補:微尺度—precondition,以及「違反了是誰的錯」)
