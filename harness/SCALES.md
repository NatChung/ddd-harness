# 尺度 × 檢查點盤點 —— 對照表縱貫追蹤、水平邊、缺口

`PIPELINE.md` 按**幕**走(每一段誰做、驗過沒有)。這一份按**尺度**走:
一類約束從訪談講出口,到實作真的被擋住,中間有幾個東西在守它、各住第幾階。

三個框架詞不在這裡定義,各有正本,**不重寫**:

| 詞 | 意思 | 正本 |
|---|---|---|
| 幕 | 什麼時候發生(時序) | `reference/0003-三幕流程與五尺度盤點.html` |
| 尺度 | 有沒有漏(清單) | 同上 |
| 階梯 | 夠不夠硬(強度,1 最強 5 最弱) | `lessons/0009-pattern-language-讓它會長大.html` |

**本檔的兩個方向**:

- **垂直** = 一個尺度沿五幕往下走,每一段有沒有東西在守 → §B
- **水平** = 同一層裡跨尺度的對齊邊(詞彙 ↔ 欄位名、契約 ↔ 測試、宣告 ↔ class)→ §C

**中尺度怎麼算**:訪談 prompt 自己寫著「中尺度 = agent 職責,屬 harness 過程層,
不在這裡填」。本檔照它,把 `relay_ledger` / `landing_check` / 結構隔離 / 雜湊防竄改 /
`verify_generated` 全部歸進中尺度那一列 —— **它們檢查的是 agent 的過程,不是領域內容**。
矩陣裡因此沒有空欄,空欄會被誤讀成「這裡沒人管」。

**每一格標了驗過還是推斷。** 標不出證據的一律寫「沒驗過」——這條是 repo 規矩,本檔不例外。

## §A 追問對照表的縱貫追蹤

`interview-prompt.md` 第三節那張表有 8 列:「聽到什麼 → 追問什麼 → 餵給哪一節」。
prompt 自己說「**問了卻沒地方放 = 白問**」。那句話只管到散文那一格;
下面把每一列一路追到 store、生成物、實作:

| 他說出這種話 | 餵給 | 尺度 | store 有位置嗎 | 誰讀它 | 最硬住第幾階 | 驗過沒有 |
|---|---|---|---|---|---|---|
| 一個**名詞** | §1 GLOSSARY | 小 | ✅ `glossary_term` | `glossary_check.py` | 2(報告) | ✅ 三份真實語料 |
| 同名不同義 | §1.1 Bounded Context | 大 | ❌ **無表** | 無 | 4 | ❌ 從沒被檢查過 |
| 一個**數字或金額** | §1 判定是不是 VO | 小 / 微 | ⚠️「DDD 型態」是自由文字 | `glossary_check` 只印 | 4 | ✅ 印得出來(ADR 0005 §4 明寫它只住第 4 階) |
| 「**當…就…**」 | §2 GWT | 需求 | ✅ `acceptance_scenario` 一族 | `gen_acceptance.py` | 3(先紅的驗收) | ✅ 但**動詞只有一個**:「送出一筆單」(票 01) |
| 「**不可以 / 一定要**」 | §3 契約 | 微 | ✅ `domain_contract` | `contract_triage.py` | 2(分診) | ✅ 但**不生任何可執行物**(票 06) |
| 「**…之後,要…**」 | §4 Domain Event | 需求 | ❌ **無表** | **無** | 4 | ❌ **從沒被檢查過** |
| 會**改變狀態**的動作 | §3 postcondition 失敗路徑 | 微 | ⚠️ `domain_contract` 有型態欄,但**沒有「失敗路徑寫了沒」這一問** | `contract_triage` | 2 | ⚠️ 分診印得出契約,印不出失敗路徑缺不缺 |
| 「**這一段誰負責**」 | §1.1 + §9 ARCHITECTURE | 大 | ✅ `architecture_rule` | `gen_archunit.py` / `package_landing_check.py` | 2(ArchUnit) | ✅ 工具驗過;⚠️ 但真跑時 §9 **落檔 0 條**(票 16 剛補 prompt,預測未驗) |
| 他**沒提到**的 | §5 明確不在範圍 / 阻斷級 | — | ❌ **無表** | **無** | 4 | ❌ 阻斷級只靠 `run_act4.sh` 的 prompt 搬條文(第 5 階) |

**這張表的讀法**:右邊三欄一路往右變弱的那幾列,就是「訪談問得很好、下游接不住」的地方。
四列 store 裡根本沒有位置 —— 而 prompt 對它們的要求跟有位置的那幾列**一樣嚴格**。

## §B 垂直:尺度 × 五幕

格子裡是**誰在守**,括號是階。`—` = 沒有東西在守。

| 尺度 | 幕一 訪談 | 幕二 落檔 | 幕三 生成 | 幕四 實作 | 幕五 review |
|---|---|---|---|---|---|
| **需求**(GWT) | `landing_check.py`(2)⚠️只查題號出現,不查記對了沒 | `schema.sql` CHECK/FK/TRIGGER(1)+ `spec_store.py` 跨列不變式(2) | `gen_acceptance.py`(3)+ `verify_generated.py`(1,逐位元組) | `acceptance_gwt.py`(3:空骨架全紅 / 可滿足 / 逐條可紅)+ `vacuous_tests.py`(2,分診) | — 人 |
| **大**(架構) | —(prompt 有盤點格,無機械檢查)(5) | `architecture_rule` schema 擋(1) | `gen_archunit.py`(2) | `acceptance_archunit.py`(3,逐條可紅)+ `package_landing_check.py`(2,宣告的 package 真的有 class) | — 人 |
| **中**(agent 職責) | `relay_ledger.verify`(1,結構上不可能再漏)+ `landing_check`(2) | bare dir 隔離(1,結構) | `verify_generated.py`(1) | 結構隔離 innerTest(1)+ 雜湊 `tamper-check`(2,**查得出、擋不住**) | — 人 |
| **小**(命名 / 詞彙) | prompt 要求禁用同義詞清單(5) | `glossary_term` / `glossary_banned_synonym` 有位置(1)+ `glossary_check.py` 對譯(2) | **—** 生成器不讀詞彙表 | **—** 沒有任何東西掃識別字(票 08-B) | — 人 |
| **微**(契約) | prompt 要求標「守在哪個聚合根內」(5) | `domain_contract` schema 擋(1)+ `contract_triage.py`(2) | **—** 契約不生任何可執行物(票 06) | 內圈測試方法名帶契約編號(5,`run_act4.sh` prompt 要求) | — 人 |

**兩條讀得出來的線**:

1. **需求那一列是唯一走完五幕的**。其餘四列都在幕三或幕四斷掉。
2. **小尺度與微尺度都在「進得了 store、出不了生成器」那一格斷**。
   兩者是同一種病:**落檔了,但沒有任何生成器認領它**,於是它到不了實作面前。

## §C 水平:同一層裡跨尺度的邊

**現存三條**,全部住第 2 階(報告與分診,不是硬擋),全部驗過:

| 邊 | 誰做 | 判什麼 | 證據 |
|---|---|---|---|
| 小 ↔ 需求(wire) | `glossary_check.py` | 每個上線的欄位名,對得到詞彙表裡的一個詞嗎 | ✅ 三份真實語料:5 欄對不到 4、7 欄一個都對不到、第三份**不適用**(不是通過) |
| 微 ↔ 需求 | `contract_triage.py` | 每條契約有沒有**指名測試**、有沒有**由誰強制** ——**兩段分開印,不合併計數** | ✅ 真跑:17 條契約,4 條有指名測試、13 條寫了理由、**兩者都有的 0 條** |
| 大 ↔ 實作 | `package_landing_check.py` | 宣告過的 package,實作完成後真的有 class 嗎(沒有 = **不適用**,不算通過) | ✅ 凍結骨架:7 宣告 / 自有 3 / **6 條規則整條不適用** |

**缺的四條邊**(都是「兩邊各自都落了檔,而沒有人比對過」):

| 缺的邊 | 為什麼要它 | 票 |
|---|---|---|
| 需求 → 微(反向) | 現在只問「契約有沒有測試蓋到」,沒問「每條情境對得到哪條契約」。單向的話,**沒有契約的情境**看不見 | **無票** |
| 小 → 實作 | 禁用同義詞清單落了檔,而 `glossary_check` **只把它印出來**,不掃任何識別字、不看任何類別名 | 08-B |
| 需求 → 大 | 情境打在哪個入口 / 碰到哪些 package,跟 §9 的相依方向對不上時沒人知道 | 13(形狀待定) |
| §5 阻斷級 → §10 不得開工 → 實作 | 條文由 `run_act4.sh` 的 prompt 搬進去(第 5 階),**沒有任何東西驗實作真的沒去碰那幾條** | **無票** |

**三個無票的共同形狀**:它們在訪談 prompt 裡都是**必填**(§4「一句都沒有的話,寫一句為什麼沒有」、

所以它們只可能活在散文裡,而散文過不了第二幕那道邊界 —— **跟票 15 是同一種失效,
只是票 15 講的是註解,這三個講的是整節。**

## 這份檔案的已知上限

- **每一格的「誰在守」是讀 code 讀出來的**(哪支工具 SELECT 哪張表),
  **不是每一格都跑過**。標 ✅ 的那幾格附了證據出處,其餘只證明「接線存在」。
- **階數是判斷,不是量測**。同一支工具在不同用法下強度不同(例:`schema.sql` 對必填欄是
  第 1 階,對「DDD 型態」那種自由文字欄只有第 4 階)。有爭議的格子以 `docs/adr/0005` 為準。
- 五尺度這個框架**是本教學自己整理的**,不是引用來的既有框架(見 `reference/0003` 末段)。
  對外講的時候要標這一層。
